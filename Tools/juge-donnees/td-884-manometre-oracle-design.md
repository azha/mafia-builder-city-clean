## 4. Cause du gel d'Oracle1 : ce qu'on sait, ce qu'on ignore
Réfuté : « le test attend une trame qui ne vient pas » (le `yield` lève et rend la main). Candidats, NON départagés : (H1) le chemin natif de `ScreenCapture` (échec « failed to generate texture » + deux copies de textures plein écran, 378 % CPU — Oracle1 est le seul à capturer deux fois) ; (H2) le balayage (≈ 1 320 `GetPixel` sur des textures invalides) ; (H3) le `TearDown()` appelé au milieu du test (l.380) avec des `Object.Destroy` différés. **D1 changera H1 et H2 à la fois** : un run vert après D1 ne dira pas LAQUELLE était la cause. Le lot ne prétend donc pas l'attribuer : il se ferme sur « plus de gel, 5/5, deux runs », et la cause reste « non attribuée, disparue avec la source de pixels » dans la dette. Une attribution coûterait des bisections hors périmètre.

## 5. Design — changer la SOURCE des pixels, pas ce qu'on juge (aucun seuil, aucune assertion existante modifié)
- **D1 — Source, qui PERSISTE (B1).** Un helper `BuildRendu()` pour Oracle1/3/4 (pas pour 2/5) : le canvas du scaffold passe en `ScreenSpaceCamera` ; une caméra orthographique (`orthographicSize` posé APRÈS `Canvas.ForceUpdateCanvases()` (lu avant, le rect vaut 1280×960 à 0,5 ⇒ 480 : sensible à l'ordre ; V31 ne le pose pas du tout et marche, `Px` annule échelle et frustum — à défaut, ne pas le poser)) vise une `RenderTexture` **1280×720 FIXE** (raison : l'hôte rend à 640×480, une RT fixe rend l'oracle indépendant de l'hôte et amène `scaleFactor` à 1, où les constantes px sont vraies). Caméra, RT et mode du canvas **restent en place pour tout le test** et sont détruits par `TearDown` (qui suit leur liste : Oracle1 en crée deux). `Capturer()` = `Canvas.ForceUpdateCanvases()` + `cam.Render()` + `ReadPixels` → `Texture2D` RGB24, à chaque fois qu'un état change. `WaitForEndOfFrame` → `yield return null` ; plus aucun `ScreenCapture`.
- **D2 — Projection (B2).** `Px(Vector3) = cam.WorldToScreenPoint` (origine bas-gauche comme `ReadPixels`), valable parce que `cam.targetTexture` fixe `pixelRect` = RT et que la caméra existe encore quand on projette (D1). Appelée sur **les coins monde** par `MeasureGeo`, `UnionMonde`, le `screenRect` d'Oracle4 ; `RayonMesure` (scalaires) projette les DEUX coins puis soustrait. `MeasureOverflow`/Oracle2 et Oracle5 **ne sont pas touchés** (Overlay, hôte, ils restent verts à 0,5) — voir §7 pour la dépendance d'hôte que cela laisse. Un détecteur grep : plus de `GetWorldCorners` consommé comme pixel dans Oracle1/3/4 sans passer par `Px`.
- **D3 — Gardes d'EFFET, en TÊTE de chaque oracle de pixels (instrument aveugle ⇒ rouge « instrument », jamais un vert sur du noir).** (a) EFFET de l'échelle, première assertion : le rayon du médaillon projeté `Px` vaut **34 ± 0,5 px** (68/2 à l'échelle 1) — ce n'est pas le paramètre (`scaleFactor`) qu'on lit, c'est le résultat ; (b) le centre et le rayon du cadran sont dans la texture ; (c) **témoin à un facteur** : deux rendus qui ne diffèrent que par `Manometre.SetActive(false)` diffèrent d'**au moins 100 pixels** dans le disque du médaillon (le patron avant/sans de V31 ; le « 100 » est un seuil CHOISI, pas hérité — V31 compte `sampled > 100` et exige `offenders == 0` ; le disque fait ≈ 3 600 px).
- **D4 — Contrôles de MUTATION sur la SCÈNE (le chaînon que les contrôles positifs existants ne voient pas : ils dégradent la texture APRÈS capture).** Corps de chaque oracle scindé en deux : capture (coroutine) + `Verdict…(données)` **synchrone** (un `yield` dans un `Assert.Throws` donnerait « aucune exception », et CS1626). Trois tests `Mutation_…` capturent la scène fautive, puis `Assert.Throws<AssertionException>(() => Verdict…)` ET exigent que le **MESSAGE** contienne la phrase de l'assertion VISÉE (jamais n'importe quelle assertion du corps : sinon un contrôle positif, l'anti-vacuité ou D3 feraient rougir pour une autre raison) : M1 `BoitierRing` forcé à `accentDanger` brut sous alarme ⇒ message « trop proche de accentDanger brut » (propriété 2, l.398 — la propriété 1 l.392 doit PASSER, c'est vérifié par le message) ; M2 `ArcTrack` masqué ⇒ message de l'arc absent des secteurs supérieurs (le fond radial reste : l'absence rougit) ; M3 `GaugeValue` à la couleur du fond local (`localBg` n'est connu qu'après une 1ʳᵉ capture, l.846 : DEUX passes — capturer, lire le fond, poser la couleur, recapturer) ⇒ message de contraste minimum. Les tests `Mutation_…` PASSENT quand l'assertion visée tombe ; si c'est une autre, ils rougissent (« rouge pour la mauvaise raison »).
- **D5 — Oracle1 (§4).** Après D1-D2 : lancé seul par nom avec timeout. Vert ⇒ « plus de gel, cause non attribuée ». Gel encore ⇒ le lot ferme ce qui tourne (2/3/4/5), Oracle1 reste en dette RÉÉCRITE avec la mesure (la trace, le dernier log), sans chasse dans ce lot. `SamplePolar` lit un tableau `GetPixels32()` pris une fois (réduit H2 sans le prétendre cause).
- **D6 — Filtre.** `ManometreOracle` reste HORS du filtre par défaut (`MafiaCI.cs`, `NonInscritesConnues`, `InscriptionDesCategoriesPlayModeTests` intacts) : l'inscrire est une décision de f2 prise sur un run vert, lot à part.
- **D7 — Valeur attendue du cadran (consigne f2 11/11).** Toute valeur attendue touchant le cadran 15/27 R est RECOPIÉE de la maquette (`.mano`, f = 15/27 ; écart mesuré au 08/10 : +0,6 px, `mesures-manometre/rayon-cadran.py`), jamais re-dérivée du code qu'elle juge ; elle porte sa source en commentaire. `ArcRadius` reste MESURÉ sur `ArcTrack`. Le lot n'ajoute aucune constante de géométrie.
