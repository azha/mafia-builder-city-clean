## 1. `shell.entree` — fondu d'entrée d'un écran d'ONGLET (160 ms, `ease-out`, `Alpha` `Multiplicatif` 0 → 1, une fois)
- **Cible = `ContentSlot`, pas « la racine du locataire »** (écart au catalogue). Le locataire est un hôte SANS `RectTransform` (`AppShell.cs:1167`), son UI naît au `Start()` suivant : aucune racine à passer à `Attacher` au montage. `ContentSlot` est l'unique `RectTransform` synchrone qui le couvre ; les barres sont ses frères (:2175-2184) et ne s'estompent pas.
- **Portée = les trois chemins qui APPELLENT `UnmountCurrentTenant`** : `MountTenant<T>` (:1563), `EnterDistrict` (:368), `MonterMenuPlus` (:1386). **Les surimpressions (`MonterLocataireEnSurimpression`, 9 sites) sont HORS L1** : elles montent PAR-DESSUS l'écran visible sans le détruire (:1573-1575) ; un fondu de `ContentSlot` ferait repartir de 0 l'écran déjà affiché (B1). Leur entrée a besoin d'une racine propre (un `RectTransform` posé par `ConstruireLocataire` autour du locataire) : **dette consignée**, pas faite ici. ⇒ le catalogue (« tout montage dans ContentSlot », l.439) est à amender : « tout montage d'onglet ».
- **Un seul helper** `AnimerEntreeDeLOnglet()` privé, appelé à la fin de ces trois chemins : `Detacher(piste précédente)` ; si `premierMontageFait` est faux ⇒ le pose et rend la main (garde F4 cold-open) ; sinon `Attacher(CatalogueHud.ShellEntree, ContentSlot, Reglage.Defaut)` (une piste ; `FinRejointLaBase` la libère, valeur finale = 1). Le cold-open monte l'onglet Empire (1ᵉʳ montage, sauté) PUIS l'Accueil en SURIMPRESSION (:1077-1078, hors L1, non animé) ⇒ rien ne s'anime pendant l'acquisition (B2 : plus de montage 2 animé). `relanceApresFermeture` est consommé à DEUX sites (:940 branche d'échec, :1074) : `premierMontageFait = false` est ré-armé à son **unique écrivain** (:1670), sinon la relance après un lancement en échec fonderait le cold-open. **Consigné, non corrigé** : pendant les 160 ms, `CanvasGroup.alpha = 0` ne bloque pas les raycasts (aucun canal n'écrit `blocksRaycasts`, `Modele.cs:12`) — l'écran encore invisible est cliquable.
- Sans régie : handle nul compté `SansRegie`, comportement d'avant. Sous `Reduit` : durée 0.
- **Quota (I1, I2) — non nouveau, à écrire** : la 16ᵉ piste non-`Ambiance` est refusée (`Regie.cs:544`, plafond 15 hors retour d'appui). Le catalogue l'a déjà mesuré (l.1190, M6) : sur ⑮ en alarme `shell.entree` ou `bandeau.entree` peut être refusé ⇒ **handle nul ⇒ pas de fondu, comportement d'avant** (jamais une erreur). G4 par écran, mesuré : transverses `"*"` 10 → 12 ; ① passe de 14 à **16 = `PistesParEcranMax` (marge 0)** : le test relit la somme, il ne la recopie pas.

Les tests qui LISENT un état de composant ne sont pas touchés ; ceux qui PHOTOGRAPHIENT (`ReadPixels`/capture/RenderTexture) et le banc des planches le sont. **Phase 0 du code, avant d'écrire** : lister ces tests par grep (monte un `AppShell` ET photographie), puis les faire poser `PoserPolitique(Reduit)`. ## 2. `bandeau.entree` — l'annonce descend et apparaît (200 ms, `ease-out`, `Bloquante = false`)
- Entrée à 2 canaux sur `rt` (le bandeau, ancré bord haut, pivot haut, `BandeauEphemere.cs:208-210`) : `TranslationY` `Additif` **+10 → 0** · `Alpha` `Multiplicatif` 0 → 1. `Attacher(…, Reglage.Defaut)`, une piste.
- **Unité (B3)** : la régie n'applique AUCUNE conversion — la valeur du canal est écrite telle quelle dans `anchoredPosition` (`Regie.cs:338-353`, `RegieInterne.cs:258-263`). Le bandeau vit sous `TopBarEchelle` (`localScale = Px(1) ≈ 3,265`, `AppShell.cs:2223-2236`) : **« +10 u » = `anchoredPosition.y = base + 10`** ; les « 27,6 px » du catalogue sont des px ÉCRAN (10 × 3,265 × 0,84375 = 27,55). Le canal porte donc **10**, pas 27,6. Test : `anchoredPosition.y − base == 10` à `Tick(0)` ET déplacement écran ≈ 27,6 px (`lossyScale`, tolérance 0,2 px).
- Dans `Annoncer` : APRÈS `SetActive(true)`, `Dimensionner()` et `groupe.alpha = 1f` (la base = l'état au repos), `Detacher(entree)` du passage précédent puis `Attacher`. Handle `entree` en champ, au côté de `fondu`.
- **Collision d'`Alpha` avec `bandeau.sortie`** (même `CanvasGroup`, `Absolu`) : `Effacement` fait `Detacher(entree)` AVANT de lancer la sortie ; `Effacer` aussi (`dureeS` peut être < 200 ms en test). Le `CanvasGroup` du bandeau est posé par le bandeau, pas par la régie : à tester que `Detacher(entree)` ne le laisse pas à une valeur ≠ 1.

Départ = même décalage dans le repère d'arrivée : `de = xArr − sens·Dx`, `vers = xArr`, `sens = +1` (s'allume) / `−1`, `Dx = Px(10)` = 42,67 u (= piste `Px(22)` − curseur `Px(10)` − 2 × retrait `Px(1)` ; revue ⊥ : exact dans les deux repères). Pendant la course la piste garde l'ancienne couleur ; `quandFini` pose la nouvelle (si l'`Image` existe encore). **Handle nul** (pas de régie / refus) ⇒ couleur finale posée aussitôt = comportement d'aujourd'hui.
